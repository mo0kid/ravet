# RAVET 0.1.0 release notes

**Released 5 November 2026** as the annotated Git tag `v0.1.0`. Packages remain
`publish = false`; depend on RAVET by tag (see
[getting started](../getting-started.md#depend-on-ravet-from-another-project)).
The [release plan](0.1.0.md) records each criterion and its evidence, and the
[CHANGELOG](../../CHANGELOG.md) lists changes since 0.0.1.

RAVET is a Rust framework for audio plug-ins and standalone applications.
0.1.0 introduces one product description and export layer, so a product writes
its processor and editor once and ships them in every supported format, instead
of writing its own format wrappers.

## Highlights

- **One product, five formats.** A [product description](../plugin-export.md)
  supplies keyed or explicit parameter IDs, format identities with overrides,
  versioned state with migration and import hooks, shared parameter text and a
  web editor. The generic CLAP export and the native VST3, AUv2, AAX and LV2
  adapters all use it; [`bundle-plugin.py`](../bundle-plugin.md) builds and
  validates them with one command, finds SDKs from a settings file or
  environment, ships licence notices in every bundle and runs a vendor signing
  hook.
- **Editors on every platform.** Web editors open on macOS, Windows and Linux in
  every format that has one there, with embedded assets of any size.
- **MIDI, latency and tail.** Note and MIDI input and output in every format
  (VST3 MIDI controllers through `IMidiMapping`), latency changes reported to
  hosts, and tails reported where the format allows (not AAX).
- **Processing policies.** Automation can keep sample offsets or apply once per
  block; bypass can be processor-owned, hard, crossfaded or frozen; a restoring
  denormal guard wraps every export and is callable from C.
- **Examples.** A [tempo-synced delay](../examples.md#tempo-synced-delay-plug-in)
  and a deterministic [instrument](../synth-plugin.md) exercise the layer.
- **Platforms and builds.** Native Linux builds, Windows cross-builds from Linux,
  and macOS arm64, x86_64 and universal bundles.
- **DSP.** A fixed-size stereo FIR and a stereo oversampler with measured cost.
- **Robustness.** The shipped surface was reviewed for panics, `unsafe` and
  exceptions crossing host boundaries (decisions 0287, 0292, 0295), and its
  dependencies audited for both licensing routes.
- **Tooling.** The umbrella crate exposes component features; Rust 1.88 is the
  declared minimum; Foundry and the starters now depend on this release tag by
  default.

## Recorded host scope

The [support matrix](../support-matrix.md) is the authoritative summary of
dated receipts. The delay example has recorded runs in:

- **macOS arm64:** REAPER 7.82 (CLAP, LV2, AUv2), Ableton Live 12 Suite (VST3),
  Logic Pro (AUv2) and Pro Tools 26.4 (AAX, vendor-signed).
- **Arch Linux x86_64 and a Windows 11 x64 VM:** REAPER 7.82 (CLAP, VST3, LV2),
  including editors.
- **macOS x86_64 under Rosetta 2:** REAPER 7.82 for CLAP, VST3, LV2 and AUv2 (not
  native Intel hardware).
- **AAX on Windows is provisional** by owner decision: built and adapter-checked,
  not run in Pro Tools for Windows.

The instrument example has REAPER runs for CLAP, VST3 and LV2 on macOS and
Linux (note onsets, CC, latency compensation, tail and MIDI output). Standalone
audio and MIDI ran on all three platforms through the DW-303 application with
named devices. These records do not certify every product, host version,
device or deadline. Validator results are listed separately in the matrix.

## Limits

- The generic layer is f32 and main bus only, with bounded events and state;
  product extra state is not persisted.
- In Pro Tools, typed editor values apply when you click away; Return and Escape
  are Pro Tools shortcuts. Windows editors do not yet follow display scaling,
  and keyboard input in Windows and Linux editors is untested.
- Native-adapter MIDI is short-message MIDI 1, without SysEx or UMP. AAX reports
  no tail (SDK 2.8 has no tail property).
- Framework dry bypass is not latency-compensated.
- The generic standalone runner (release plan §3) is deferred: standalone
  applications use `StandaloneWindow` and the device crates directly.
- VST2 is excluded. External SDKs and proprietary consumer code are not
  distributed with RAVET.

See the [catalogue](../FEATURES.md) for each feature's exact limits.

## Upgrading from 0.0.1

The [compatibility policy](../compatibility.md) starts with 0.1.0. It does not
retroactively guarantee 0.0.1 state formats or parameter numbering. During
0.x, minor releases may break APIs; patch releases must remain compatible.
Implemented state formats written from 0.1.0 onward must remain readable by
newer releases; prototype formats may change between minors and reject unknown
versions. Public Rust/native APIs remain governed by feature status.

When moving a product to `ravet-plugin`:

1. Preserve its released format identities with `IdentityOverrides`; do not
   assume the new derived identities match an old wrapper. Legacy reference
   adapters remain available explicitly in their format guides.
2. Give every parameter a permanent key. Use `Parameter::with_id` to preserve
   existing host IDs; otherwise IDs derive from the key rather than declaration
   order. Check collision rejection and keep removed IDs retired. Preserve
   released ranges and bus layouts deliberately.
3. Choose a product `StateFormat` tag/version. The new `RAVETSTA` envelope stores
   format/product versions and parameter ID/value pairs. It matches by ID,
   defaults missing values, drops unknown IDs and rejects invalid/newer state
   transactionally. Implement `migrate_state` for earlier product versions and
   `import_state` for 0.0.1 or foreign wrapper bytes. No universal import is
   supplied, and product extra data is not persisted by current exports.
5. Enable the `ravet-plugin` `editor` feature (umbrella `plugin-editor`) if the
   product has a web editor; `clap` and `native` no longer pull it in.
4. Test old sessions and presets through each target adapter, including a
   main-thread parameter edit saved before audio runs. The new cache handles
   this path, but a product's migration and identity choices still need tests.

Saved-state, preset and parameter-ID changes for the other formats, including
`RVETTREE` format 2 for `.ravetpreset` files, are listed in the
[0.1.0 upgrade notes](0.1.0-upgrade.md).

Use Rust 1.88 or later and select the umbrella features needed by the consumer;
`ravet-embedded` stays a separate dependency. XML-only `ravet-data` consumers
need no new feature; users of hashing/compatibility crypto or signed claims
must enable `crypto` or `entitlement` respectively.

## Distribution and contributions

This release has no crates.io package or binary download. The source edition
is GPL-3.0-only; commercial terms and dependency obligations remain as described
in [LICENSING](../../LICENSING.md). This page grants no additional rights.
RAVET accepts no outside pull requests or code contributions. Reports,
questions and host evidence are welcome as issues; see
[CONTRIBUTING](../../CONTRIBUTING.md).
