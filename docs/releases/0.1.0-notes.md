# RAVET 0.1.0 release notes

*Released 5 November 2026 as the Git tag `v0.1.0`.*

RAVET is a Rust framework for building audio plug-ins and standalone apps.
The big change in 0.1.0 is that you describe your product once, with its
processor, parameters, saved state and editor, and RAVET builds it in every
supported format. You no longer write a wrapper for each format yourself.

There's no crates.io package yet. To use RAVET, depend on the tag; the
[getting started guide](../getting-started.md#depend-on-ravet-from-another-project)
shows how. The [CHANGELOG](../../CHANGELOG.md) lists everything that changed
since 0.0.1.

## What's new

**Plug-in export.** You write your plug-in once and RAVET builds it as CLAP,
VST3, AU, AAX and LV2. The [product description](../plugin-export.md) covers
parameter IDs, format identities, saved state with migration, parameter text
and a web editor. [`bundle-plugin.py`](../bundle-plugin.md) builds and
validates every format in one go. It finds your SDKs, adds licence notices to
each bundle and can run your signing step.

**Editors.** Web editors work on macOS, Windows and Linux, in every format that
supports an editor on that platform.

**MIDI, latency and tails.** MIDI in and out works in every format. Plug-ins
can tell the host when their latency changes, and can report a tail wherever
the format supports one.

**Automation and bypass.** Automation can be applied sample-accurately or once
per block. Bypass can be handled by your processor or by RAVET, as a hard
switch, a crossfade or a frozen pass-through. Denormals are handled in every
format.

**Examples.** A [tempo-synced delay](../examples.md#tempo-synced-delay-plug-in)
and an [instrument](../synth-plugin.md) show the whole workflow.

**Platforms.** Native Linux builds, Windows builds cross-compiled from Linux,
and macOS bundles for Apple silicon, Intel or both.

**DSP.** A stereo FIR filter and a stereo oversampler.

**Robustness.** We reviewed the code that runs inside hosts for panics, unsafe
code and errors that could reach the host, and checked every dependency's
licence.

**Tooling.** Rust 1.88 is now the minimum. New projects from Foundry and the
starter templates use this release by default.

## Where it's been tested

The delay example has been run in:

- **macOS (Apple silicon):** REAPER (CLAP, LV2, AU), Ableton Live 12 (VST3),
  Logic Pro (AU) and Pro Tools (AAX).
- **Linux and Windows 11:** REAPER (CLAP, VST3, LV2), editors included.
- **macOS (Intel, under Rosetta):** REAPER (CLAP, VST3, LV2, AU).

AAX on Windows builds and passes our checks, but hasn't been run in Pro Tools
for Windows yet, so treat it as provisional.

The instrument example has been run in REAPER on macOS and Linux. Standalone
audio and MIDI have been run on all three platforms through
[DW-303](https://github.com/mo0kid/dw-303).

The [support matrix](../support-matrix.md) has the full list, with dates and
versions. Testing in these hosts doesn't guarantee every host, version or
device will behave the same.

## Known limitations

- Plug-ins built with the export layer process 32-bit float audio on a single
  main bus.
- In Pro Tools, a value typed into the editor is applied when you click away.
  Pro Tools keeps Return and Escape for itself.
- Windows editors don't yet follow display scaling, and typing into editors on
  Windows and Linux hasn't been tested.
- MIDI in VST3, AU, AAX and LV2 is MIDI 1 short messages only, with no SysEx
  or MIDI 2.
- AAX can't report a tail, because the AAX SDK has no way to.
- When RAVET handles bypass, the dry signal isn't latency-compensated.
- There's no generic standalone runner yet. Standalone apps use
  `StandaloneWindow` and the audio and MIDI device crates directly.
- VST2 isn't supported and won't be.

The [feature catalogue](../FEATURES.md) lists the exact limits of each feature.

## Upgrading from 0.0.1

From 0.1.0 on, saved state will stay readable by later releases. Until 1.0,
minor releases may still change APIs; patch releases won't. The
[compatibility policy](../compatibility.md) has the details. There's no
guarantee for state saved by 0.0.1.

If you're moving an existing plug-in onto the new export layer:

1. **Keep your format identities.** Set them with `IdentityOverrides`, so hosts
   still recognise your plug-in. New identities won't match your old wrapper.
2. **Give every parameter a permanent key.** Use `Parameter::with_id` to keep
   the host IDs you've already released. Don't reuse IDs you've removed.
3. **Choose a state format.** Implement `migrate_state` to read older versions
   of your own state, and `import_state` to read state saved by your old
   wrapper.
4. **Turn on the editor feature** (`plugin-editor` on the `ravet` crate) if
   your plug-in has a web editor.
5. **Test old sessions and presets** in every format you ship.

The [0.1.0 upgrade notes](0.1.0-upgrade.md) cover the remaining saved-state,
preset and parameter-ID changes.
