# RAVET 0.1.0 release notes

**Draft — not released.** Evidence snapshot: 5 November 2026, through
`628af5d` plus the documentation/CI change. Workspace packages still identify
as 0.0.1, remain `publish = false`, and no `v0.1.0` tag is created by this work.
The [release plan](0.1.0.md) records outstanding criteria;
[CHANGELOG](../../CHANGELOG.md) lists changes since 0.0.1.

RAVET is a Rust framework for audio plug-ins and standalone applications.
This milestone introduces a common product description and export layer so
products can reuse format adapters instead of writing gain-specific wrappers.
The new adapters remain prototypes with the limits below.

## Highlights

- [One product description](../plugin-export.md) supplies keyed or explicit
  parameter IDs, deterministic format identities with overrides, versioned
  state with migration/import hooks, shared parameter text and a macOS editor.
  Generic CLAP and native VST3, AUv2, AAX and LV2 adapters use it.
- Automation can retain sample offsets or collect values at block start.
  Bypass can be processor-owned, hard, crossfaded or frozen. Export processing
  uses a restoring denormal guard by default.
- The [Delay example](../examples.md#tempo-synced-delay-plug-in) demonstrates
  host-tempo sync, feedback tone, ping-pong, smoothing and typed values.
- Bundle scripts support native Linux and Windows cross-builds.
  The [REAPER harness](../host-validation.md#scripted-ravet-delay-check-any-format-macoslinuxwindows)
  checks synthetic renders, parameter readback and saved-project recall.
- The umbrella crate exposes component features; internal libraries have
  version requirements, Rust 1.88 is the declared minimum, and `ravet-data`
  cryptography is opt-in. Starters/Foundry can select a tagged source.
- Hosted macOS/Windows CI is configured for portable tests, generic exports,
  Delay CLAP packaging and checksum-pinned clap-validator. These workflows
  have not run for this change.

## Recorded host scope

The [support matrix](../support-matrix.md) is the authoritative summary of
dated receipts and validator results. Delay has recorded runs in:

- macOS arm64: REAPER 7.82 (CLAP/LV2), Ableton Live 12 Suite (VST3),
  Logic Pro (AUv2; version not recorded) and Pro Tools 26.4 (AAX).
- Windows 11 x64 VM and Arch Linux x86_64: REAPER 7.82 (CLAP/VST3/LV2).
- Windows AAX is **provisional by owner decision**: built and adapter-checked,
  but not run in Pro Tools for Windows or Avid's validator.

REAPER and exact-value Live renders pass sample checks. Logic's manual bounces
include metronome clicks; Pro Tools timing checks pass but strict amplitude
checks fail because values were not set exactly. Only Logic has the recorded
manual editor reopening and project reopening check for its new native adapter.
These observations do not establish every product, DAW version, device or
deadline. Validator checks are listed separately in the matrix.

## Limits

The generic layer is f32/main-bus only, uses bounded events/state and has
macOS editors only. Windows/Linux editors are not yet supported. Pro Tools
keeps keyboard input from the web editor; mouse editing works. Generic CLAP
has no note output, and generic exports do not persist product extra state.
MIDI in the native adapters is short-message MIDI 1, without SysEx/UMP.
Framework dry bypass is not latency-compensated. See the
[catalogue](../FEATURES.md) for exact feature limits.

Standalone runner/editor/FIR work, macOS x86_64 host runs, remaining audits,
release version/tag/default-source changes and the external example-product
release remain open in the plan. VST2 is excluded. External SDKs and proprietary
consumer code are not distributed with RAVET.

## Upgrading from 0.0.1

The [compatibility policy](../compatibility.md) starts with 0.1.0. It does not
retroactively guarantee 0.0.1 state formats or parameter numbering. During
0.x, minor releases may break APIs; patch releases must remain compatible.
Implemented state formats written from 0.1.0 onward must remain readable by
newer releases; prototype formats may change between minors and reject unknown
versions. Public Rust/native APIs remain governed by feature status.

When moving a product to `ravet-plugin`:

1. Preserve its released format identities with `IdentityOverrides`; do not
   assume the new derived identities match an old wrapper. Legacy reference
   adapters remain available explicitly in their format guides.
2. Give every parameter a permanent key. Use `Parameter::with_id` to preserve
   existing host IDs; otherwise IDs derive from the key rather than declaration
   order. Check collision rejection and keep removed IDs retired. Preserve
   released ranges and bus layouts deliberately.
3. Choose a product `StateFormat` tag/version. The new `RAVETSTA` envelope stores
   format/product versions and parameter ID/value pairs. It matches by ID,
   defaults missing values, drops unknown IDs and rejects invalid/newer state
   transactionally. Implement `migrate_state` for earlier product versions and
   `import_state` for 0.0.1 or foreign wrapper bytes. No universal import is
   supplied, and product extra data is not persisted by current exports.
4. Test old sessions and presets through each target adapter, including a
   main-thread parameter edit saved before audio runs. The new cache handles
   this path, but a product's migration and identity choices still need tests.

Use Rust 1.88 or later and select the umbrella features needed by the consumer;
`ravet-embedded` stays a separate dependency. XML-only `ravet-data` consumers
need no new feature; users of hashing/compatibility crypto or signed claims
must enable `crypto` or `entitlement` respectively.
