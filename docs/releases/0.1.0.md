# RAVET 0.1.0 release plan

**Status:** Not released. This page lists the criteria the release must meet.
See also the [draft release notes](0.1.0-notes.md) and
[evidence-only support matrix](../support-matrix.md).
The [feature catalogue](../FEATURES.md) and [work status](../WORK_STATUS.md)
record what is currently implemented. Scope and distribution are set by
[decision 0279](../decisions/0279-release-0-1-0-scope-and-distribution.md).

0.1.0 aims to let a developer build, validate and ship a plug-in or standalone
product without writing their own format wrapper. Feedback from private
consumer products built on the [0.0.1 preview](0.0.1.md) shaped these criteria.

## 1. Dependency and versioning

- [x] Give the umbrella `ravet` crate a Cargo feature and module re-export for
      every component crate except `ravet-embedded`, so consumers declare a
      single dependency. See [getting started](../getting-started.md#depend-on-ravet-from-another-project).
- [x] Give every internal library dependency a version requirement, through
      `[workspace.dependencies]`. Dev-dependencies on unpublished examples and
      tools stay path-only.
- [x] State and verify a minimum supported Rust version: `rust-version = "1.88"`,
      checked in CI with every target and feature.
- [x] Complete package metadata (`repository`, `homepage`, `documentation`,
      `readme`, `keywords`, `categories`), inherited from the workspace.
      Packages remain `publish = false`.
- [x] Make `ravet-data` cryptography opt-in (`crypto`, `entitlement`
      features), so XML-only use compiles no hashing or signature code.
- [x] Review other heavy dependencies for opt-in features: the web editor
      (`ravet-webview`) is the `ravet-plugin` `editor` feature; `sha2` and
      `serde_json` stay required ([dependency notices](../dependency-notices.md#opt-in-review)).
- [x] Let starters and Foundry projects depend on the tagged release, with
      every RAVET dependency from one source (`--ravet-source tag`,
      `framework_source = "tag"`). Local paths remain the default between releases.
- [ ] Make the release tag the default source for starters and Foundry in the
      release commit.
      Remaining: release-time default switch; local paths are still the default.
- [x] Make the repository public, so tag dependencies can be fetched without
      credentials.
- [x] Publish a semantic-versioning and deprecation policy for 0.x releases:
      [versioning and compatibility](../compatibility.md).
- [x] Publish a compatibility policy for saved state, presets and parameter IDs
      (same page).
- [x] Bring existing state formats and parameter IDs into line with the policy
      (format versions on all saved state, caller-keyed parameter IDs). The
      [upgrade notes](0.1.0-upgrade.md) list each format, its version marker
      and migration path; `RVETTREE` presets moved to format 2 with a product
      schema version and still read 0.0.1 records.

## 2. Generic plug-in export layer

A single supported layer exports a RAVET processor and editor as VST3, AU,
AAX, CLAP and LV2. It replaces the gain-only reference adapters. The accepted
design is [decision 0281](../decisions/0281-generic-export-layer.md).
Progress: `ravet-plugin` supplies product descriptions, format identities,
versioned state, editor protocol, automation/bypass policies, generic CLAP and
the C table. Generic [VST3](../vst3.md), [AUv2](../audio-unit.md),
[AAX](../aax.md) and [LV2](../lv2.md) adapters now use it; their limits and
recorded runs are in the [support matrix](../support-matrix.md). DW-303,
an open-source instrument in its own repository, remains the intended pilot
product; its publication/build criterion below is still open. The layer must
provide:

- [x] stable host parameter IDs, including caller-supplied IDs for products that
      must keep compatibility with existing sessions; `Parameter::with_id` or
      key-derived IDs, order independence and identity overrides are covered by
      [product tests](../../crates/ravet-plugin/tests/product.rs) and the
      [guide](../plugin-export.md#product-description).
- [x] a selectable automation policy: sample-accurate, or one value per block;
      both exports use `PolicyProcessor`; offset/order tests are in
      [policy tests](../../crates/ravet-plugin/src/policy/tests.rs), with
      [recorded validation](../WORK_STATUS.md#release-010-native-table).
- [x] a host-bypass policy, including frozen DSP history and a bypass path
      that avoids scratch-buffer copies; frozen mode uses in-place no-op or
      direct `AudioBuffer::pass_through`, covered by
      [policy tests](../../crates/ravet-plugin/src/policy/tests.rs) and
      [buffer tests](../../crates/ravet-foundation/tests/pass_through.rs).
      Other dry bypass policies retain prepared scratch; see the
      [scope](../plugin-export.md#automation-and-bypass-policies).
- [x] parameter changes made by the host on the main thread reaching the saved
      state before the next processing block; cache-backed state is checked by
      `host_changes_reach_the_processor_and_saved_state` in the
      [table tests](../../crates/ravet-plugin/src/native/tests.rs), with
      [AUv2 pre-render state evidence](../WORK_STATUS.md#release-010-auv2-adapter)
      and the [CLAP flush contract](../plugin-export.md#clap-export).
- [x] hooks for importing earlier state formats and keeping existing plug-in
      identities; migration/foreign import and identity overrides are covered by
      [state tests](../../crates/ravet-plugin/tests/state.rs) and
      [product tests](../../crates/ravet-plugin/tests/product.rs).
      Product-specific import implementations remain the consumer's work.
- [ ] MIDI input and output, including MIDI controllers on VST3, plus latency
      and tail reporting;
      Evidence Synth now exercises generic MIDI I/O/CC and changing latency, including VST3 IMidiMapping, with [recorded checks](../synth-plugin.md). CLAP output is implemented. Keep this item open: AAX SDK 2.8 has no native tail report here, and macOS instrument host attempts did not reach the script.
- [x] editor lifetimes that survive hosts which keep a view after disposing the
      plug-in (AU); the [native AUv2 adapter](../audio-unit.md) has actual-component
      retained-view disposal evidence;
- [x] SDK discovery and build integration that do not rely on paths into another
      project; see the [unified bundle tool](../bundle-plugin.md);
- [x] a documented denormal guard (`ScopedDenormalMode`) reachable from Rust
      and the C ABI, applied by default in the processing entry points.
      Rust `ScopedDenormalMode` and the synchronous C callback `ravet_plugin_with_denormal_mode_v1` are documented and tested; all five exports dispatch product DSP under default FlushBoth ([contract and entry-point audit](../plugin-export.md#denormal-guard)).

- [ ] DW-303 builds on the layer from a RAVET tag, and its repository is
      reviewed and published as the open-source example product.
      Remaining: record the tag-based DW-303 build, repository review and publication; no such receipt is on this branch.

## 3. Standalone runner — deferred to after 0.1.0

**Owner decision, 5 November 2026:** these framework conveniences move to a
later release. Standalone applications are proven in practice for 0.1.0: the
DW-303 application, built on RAVET's `StandaloneWindow`, the standard
Audio/MIDI popup and the device/MIDI crates, runs on macOS, Windows and Linux
(owner report; audio and MIDI exercised on macOS). DW-303 currently does each
item below in its own code: it lists devices with `ravet_device`, owns its
stream lifecycle and state file, and delivers MIDI at block start. The items
remain the plan for a generic standalone runner; none is required for 0.1.0.

- [ ] A device-inventory provider for the standard Audio/MIDI settings popup,
      so applications do not enumerate devices themselves.
      Remaining: complete and validate the runner-owned inventory provider (`standalone runner` work package).
- [ ] MIDI outputs in the popup.
      Remaining: output selection and its runner integration are not evidenced by the current input-only popup.
- [ ] Engine ownership across stream rebuilds, without locks in the audio
      callback.
      Remaining: record runner-owned stream rebuilds and lock-free callback ownership.
- [ ] MIDI timestamps mapped to sample offsets.
      Remaining: runner/device timestamp mapping needs its own end-to-end evidence.
- [ ] Optional headless operation when no device is available.
      Remaining: runner-level no-device fallback needs implementation/validation; headless fixtures alone are insufficient.
- [ ] Saving state on quit, a fixed-size window option, and the product name in
      the application menu.
      Remaining: verify the complete runner quit/window/menu contract in the standalone work package.
- [ ] Save, folder and multiple-selection file dialogs with Rust bindings.
      Remaining: complete and validate the full dialog set; partial native bindings do not close it.

## 4. Editor and DSP gaps

- [ ] Loading web editor assets larger than the 64 KiB snapshot limit without
      chunked base64 transfer.
      Remaining: the editor asset transport work package must close this limit; accepting 1 MiB product HTML alone is not transport evidence.
- [ ] A fixed-size stereo FIR and oversampler path with competitive per-block
      cost. Progress: `StereoFir` and `StereoOversampler` exist with
      [benchmarks](../signal-processing.md#stereo-block-fir-and-oversampling);
      f32 FIR cost matches Apple Accelerate `vDSP_conv` at 256–1,024 taps on
      one Apple M4 Pro, and the oversampler is about 3.3× faster than the
      per-sample path. Open: no external oversampler baseline, no native
      x86_64 measurement.
- [ ] The Linux plug window mapped inside non-XEmbed parents, with recorded
      host evidence.
      Remaining: generic Linux editors are not supported; no non-XEmbed host run is recorded.

## 5. Platform and host evidence

Each combination below needs a recorded run in a named host before it is
claimed. Format validators (Steinberg validator, clap-validator, `auval`,
`lv2lint`) are required but not sufficient.

| Format | macOS | Windows | Linux |
|---|---|---|---|
| VST3 | [x] Ableton Live 12 | [x] REAPER 7.82 | [x] REAPER 7.82 |
| CLAP | [x] REAPER 7.82 | [x] REAPER 7.82 | [x] REAPER 7.82 |
| LV2 | [x] REAPER 7.82 | [x] REAPER 7.82 | [x] REAPER 7.82 |
| AU | [x] Logic Pro | — | — |
| AAX | [x] Pro Tools 26.4 | provisional | — |

Ticked cells have a recorded run of the RAVET Delay example in the named host;
see the [support matrix](../support-matrix.md) for dates, exact scope and receipts
(5 November 2026). REAPER and exact-value Live exports pass strict sample checks.
Logic's bounces contain metronome clicks; Pro Tools echo timing is measured but
its strict amplitude checks fail because values were not set exactly. Logic's
version was not recorded. These limits remain part of the evidence.
macOS runs are on arm64; Linux on Arch x86_64; Windows on Windows 11 x64 (a
VM, WaveOut audio).

**AAX on Windows is provisional for 0.1.0** (owner decision, 5 November 2026):
the bundle builds for Windows x64 and passes RAVET's own adapter checks in a
Windows 11 VM, but it has not been run in Pro Tools for Windows, and Avid's
validator has not been run. The support matrix lists it as provisional rather
than supported. Signing remains the plug-in vendor's step.

- [ ] Standalone audio and MIDI on each platform with a named device.
      Progress (owner report, 5 November 2026): the DW-303 standalone app, built
      on RAVET's `StandaloneWindow` and Audio/MIDI popup, has run on macOS,
      Windows and Linux; audio output and MIDI input were exercised on macOS.
      Remaining: audio and MIDI runs on Windows and Linux, and device names for
      each recorded run.
- [ ] Both macOS architectures (arm64 and x86_64) built and run.
      Remaining: equivalent macOS x86_64 builds and runtime evidence.
- [ ] Hosted macOS and Windows CI on every push to `main`.
      Configuration added in [portable-release.yml](../../.github/workflows/portable-release.yml); remaining: execute hosted jobs after merge/push to `main`. No hosted pass is claimed.
