# Upgrading from 0.0.1 to 0.1.0

**Status:** 0.1.0 is not released. This page collects the upgrade notes for
saved state, presets and parameter IDs as the changes land; the release
changelog will repeat them. The rules they follow are in
[versioning and compatibility](../compatibility.md).

## Saved-state and parameter-ID inventory

Every format that RAVET writes in the supported surface was checked against the
policy on 5 November 2026: it must carry a format version, reject versions it
does not understand, and identify parameters by stable product-supplied IDs.

| Format | Where | 0.0.1 | 0.1.0 | Migration |
|---|---|---|---|---|
| Plug-in state envelope `RAVETSTA` | `ravet-plugin` [state](../plugin-export.md#saved-state) | New in 0.1.0 | Envelope version 1 plus product tag and product state version; newer versions reject (`UnsupportedEnvelope`, `TooNew`) | `StateHooks::migrate` for earlier product versions; `StateHooks::import` for foreign data |
| Plug-in parameter IDs | `ravet-plugin` [product](../plugin-export.md#product-description) | New in 0.1.0 | Explicit `Parameter::with_id`, or FNV-1a of the key; never declaration order | Use `with_id` to keep IDs a product already released |
| Observable-tree records `RVETTREE` | `ravet-state` [observable state](../observable-state.md) | Format 1: version, no product schema; any other version failed as `InvalidRecord` | **Format 2** adds a product schema version; newer formats reject with `UnsupportedVersion`, newer schemas with `UnsupportedSchema` | Format 1 still decodes, as schema 1. `Store::restore_migrating` migrates older schemas |
| Preset files `.ravetpreset` | `ravet-preset` [preset files](../preset-files.md) | `RVETTREE` format 1 | `RVETTREE` format 2 at the library's schema (`with_schema`, default 1) | 0.0.1 files load unchanged; `load_into_migrating` for older schemas |
| Foundation parameter records | `ravet-foundation` [parameters](../parameters.md) | Product ID, version, ID/value pairs; exact version only | Unchanged; adds `parameter_record_version` to read the version first | Decode at the saved version, then `ParameterState::migrate` by ID |
| Native parameter and state tables | `ravet-native` `RavetNativeParameters.h`, `RavetNativeState.h` | Table ABI version 1; `state_product`/`state_version`; explicit `uint32_t` IDs | Unchanged | Consumer decoders can migrate earlier records explicitly |
| Generic native table `RavetPlugin.h` | `ravet-plugin` | New in 0.1.0 | Table version 1; each parameter carries its permanent ID and key; indices are positions only | — |
| Generic VST3, AU, AAX, CLAP and LV2 adapters | `ravet-plugin` | Gain-only references | Store the `RAVETSTA` envelope; host parameter IDs are the permanent IDs (AAX `p<hex ID>`; LV2 port symbol = key) | — |
| Gain reference record `RAVETGN\0` | `examples/gain`, gain VST3/AU/AAX/LV2/CLAP references | Version 2, explicit IDs 1 and 2 | Unchanged | Version 1 migrates with bypass off |
| Native example records (`RAVETPS\0`, `RAVETMS\0`, `RAVETBUS`, `RAVETNTE`, `RAVETDLY`, `RAVETRBS`, `RAVETRDL`) | `examples/*-native` | Foundation records, version 1, explicit IDs | Unchanged | — |
| Sine CLAP record `RVETSIN1` | `examples/sine-clap` | Version in the magic; anything else rejects | Unchanged (teaching example) | — |
| Foundry project settings | `tools/foundry` | `schema_version = 1`; others reject | Unchanged | — |

### LV2 port indices

LV2 identifies a port by its index in the plug-in binary and by its symbol in
saved sessions. The generic LV2 adapter gives each parameter its key as symbol,
and assigns indices in declaration order after the fixed ports. Symbols are
therefore stable, but **inserting, removing or reordering parameters changes
later port indices**. Hosts that store indices rather than symbols would then
misassign values. Add new parameters at the end of the product description,
and keep removed parameters as hidden, read-only entries if released LV2
sessions must keep loading. See [LV2](../lv2.md#generated-metadata-and-ports).

## Breaking changes and migration steps

1. **`RVETTREE` records are written in format 2.** `Store::encode` and
   `PresetLibrary::save` now emit a 24-byte header (four bytes longer) with the
   product schema version. RAVET 0.0.1 cannot read these records; 0.1.0 reads
   both. Code that parsed record bytes at fixed offsets must skip the extra
   four bytes. No action is needed for code that uses the `ravet-state` API.
2. **New `ravet_state::StateError` variants** `UnsupportedVersion(u32)` and
   `UnsupportedSchema(u32)`. Exhaustive `match` statements need arms for them.
   A record with an unknown format version previously failed as `InvalidRecord`.
3. **`Limits::bytes` must be at least 24** (was 20), the format-2 header size.
4. **Preset schemas.** Products whose tree layout changes should set
   `PresetLibrary::with_schema` to a new schema and load older presets with
   `load_into_migrating`. `load_into` rejects older schemas with
   `StateError::InvalidOperation` rather than reading them as current.

## Additions

- `ravet_state::{TREE_MAGIC, TREE_FORMAT_VERSION, DEFAULT_SCHEMA, TreeHeader,
  read_header}`, `Store::{encode_schema, decode_schema, restore_migrating}`.
- `ravet_preset::PresetLibrary::{with_schema, schema, load_into_migrating}`.
- `ravet_foundation::parameter_record_version`.
